Before you start: audio route

With Bluetooth headphones connected, iOS switches them from stereo playback to the low-quality call profile whenever any app wants the microphone, and switches back after. That negotiation is a strong suspect on its own, so record which route you are on — and ideally run this page once with Bluetooth connected and once without.

Which one breaks the microphone?

Wait for the test to say the microphone is released before switching apps. Leaving early means it was still legitimately open, which tells us nothing. Run one test, wait for the release, then switch to your dictation app and try to talk. Come back and record what happened.

D · Recognition, then a plain stream

The same speech recognition as test C, but immediately afterwards it opens and closes a bare microphone stream — the thing test A showed to be harmless. If that resets whatever recognition leaves behind, this is the fix. If not, the Web Speech API is a dead end on this phone and the app should transcribe some other way.
