Before you start: audio route

With Bluetooth headphones connected, iOS switches them from stereo playback to the low-quality call profile whenever any app wants the microphone, and switches back after. That negotiation is a strong suspect on its own, so record which route you are on — and ideally run this page once with Bluetooth connected and once without.

Which one breaks the microphone?

Three different ways a web page can use the mic. Run one, then switch to your dictation app and try to talk. Come back and record what happened. Force-quit and reopen the dictation app between tests so each one starts clean.

A · Microphone stream only

Opens the mic for 5 seconds and closes it. No recording, no recognition. The plainest possible use.

Not run

B · Recording

Records 5 seconds of audio with MediaRecorder, then stops and closes the mic. This is what Phase 2 would use.

Not run

C · Speech recognition

Runs speech recognition for 5 seconds, then stops and aborts it. This is what the app does today.
